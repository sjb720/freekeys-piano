# Main process — `src/main/`

| Name                               | File             | Description                                                                                                                                                                                                                                           |
| ---------------------------------- | ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `createMainWindow()`               | `window.ts`      | Sandboxed, context-isolated window with autoplay allowed. Starts fullscreen; F11 (Ctrl+Cmd+F on macOS) toggles it via the default menu. Blocks in-app navigation; https links open externally. Loads the dev server URL or `app://bundle/index.html`. |
| `registerSchemePrivileges()`       | `protocol.ts`    | Registers `app://` as standard/secure/fetch-capable. Must run before `ready`.                                                                                                                                                                         |
| `serveDirectory(root)`             | `protocol.ts`    | Serves files from `root` over `app://`, rejecting path traversal.                                                                                                                                                                                     |
| `resourcesDir()` / `rendererDir()` | `paths.ts`       | Bundled resources (`resources/` in dev, `process.resourcesPath` when packaged) and the built renderer.                                                                                                                                                |
| `registerHandlers(library)`        | `handlers.ts`    | Registers all IPC handlers, including the file and folder dialogs.                                                                                                                                                                                    |
| `configurePermissions()`           | `permissions.ts` | Grants only `midi` and `midiSysex` (Chromium's name for every Web MIDI request); denies everything else.                                                                                                                                              |
| `isAllowedPermission(name)`        | `permissions.ts` | The allow-list check used by both permission handlers.                                                                                                                                                                                                |

## `library/`

| Name                           | File               | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------ | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Library`                      | `Library.ts`       | `new ({ db, profile, bundledDir, importDir, runner, onStatus })`. Facade over the library tables and the scanner. `profile()` returns the active profile id, which decides `favorite`. Roots are `bundledDir`, `importDir` (source `imported`), and every library folder. Methods: `list`, `get`, `folders`, `addFolder` (starts a scan), `removeFolder`, `importFile(path)`, `importFiles(paths)` (copies MIDI files into `importDir` as `<name>.mid`, checking only the 14-byte `MThd` header rather than the extension; skips unreadable files, non-MIDI, and songs already in the library or earlier in the batch; renames clashes to `name (2).mid`; analyzes the copies in one `runner` batch, deleting any that fail; returns `ImportResult`), `load(id)`, `setFavorite` (needs a profile), `setHands` (re-analyzes in place). |
| `LibraryDb`                    | `LibraryDb.ts`     | Queries over `folders`, `songs` (summary, difficulty JSON, `analysis_version`, hands), `files` (path → song, source, folder, mtime, size; `song_id` null for unreadable files), and `favorites`. A song's source is its best file: bundled, library, imported, then file. `inLibrary(id)` is true when a non-`file` source has the song.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `Scanner`                      | `Scanner.ts`       | `scan()` walks each root, deletes rows for missing files, and queues new or changed files (by mtime and size) plus songs below `ANALYSIS_VERSION`. Results commit in batches of 50 with a status update each. Calls during a scan queue one more pass. `changed()` bumps `revision`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `walkMidi(dir)`                | `Scanner.ts`       | Recursive `.mid`/`.midi` finder with mtime and size.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `AnalyzeRunner`                | `Scanner.ts`       | `(paths, overrides, onResult) => Promise<void>`. Tests run it inline.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `runInUtilityProcess`          | `utilityRunner.ts` | Production runner. Forks `libraryWorker.js` (`worker.ts`) for each scan.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `analyzeFile(path, overrides)` | `analyzeFile.ts`   | Reads, hashes (`songIdFor`), and summarizes one file. Returns `{ path, id, summary }` or `{ path, error }`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `titleFromPath`                | `analyzeFile.ts`   | Fallback title when the MIDI has no name.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

## `db/` and `profiles/`

| Name                                             | File                    | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------ | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `openDatabase(path)`                             | `db/openDatabase.ts`    | Opens `node:sqlite` with WAL and foreign keys, and creates every table (library, `profiles`, `settings`, `favorites`, `sessions`).                                                                                                                                                                                                                                                                                                                                                             |
| `transaction(db, fn)` / `databasePath(userData)` | `db/openDatabase.ts`    | Begin/commit/rollback wrapper; `app.db` in Electron's `userData`.                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `Profiles`                                       | `profiles/Profiles.ts`  | Holds the active profile for the app session (always `null` at launch). `list`, `active`, `create`/`update` (validated with `profileInputError`, names unique ignoring case), `delete` (also clears its settings, favorites, and selection), `select(id \| null)` (updates `lastUsedAt`). `loadSettings()` merges app-scope values with the active profile's, dropping invalid or wrong-layer values. `setSetting(key, value)` validates and writes to the scope the registry's `layer` names. |
| `ProfileDb` / `APP_SCOPE`                        | `profiles/ProfileDb.ts` | Row access for `profiles` and `settings` (`scope` is `'app'` or a profile id; values are JSON).                                                                                                                                                                                                                                                                                                                                                                                                |

`scripts/generate-demos.mts` (`pnpm demos`) builds the demo MIDIs from note lists.

## `history/`

| Name      | File         | Description                                                                                                                                                                                                                                                                                                                                                                               |
| --------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `History` | `History.ts` | `new (db, profile)`. `record(input)` validates and saves for the active profile. `summary(today)` returns total and today's time, session count, streaks, the last `CHART_DAYS` (14) days, and the 8 most recent sessions with song titles. `song(id)` returns time, sessions, completions, last played, and best scores for the active profile. Sessions are deleted with their profile. |

## Packaging and releases

| File                            | Description                                                                                                                                                                                                                                                                 |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `electron-builder.yml`          | Linux AppImage and deb, Windows NSIS installer. Artifact names: `FreeKeys-<v>-linux-<arch>.AppImage`, `freekeys_<v>_<arch>.deb`, `FreeKeys-<v>-windows-setup.exe`. Bundled songs ship from `resources/songs` (subfolders and `CREDITS.md` included) to `<resources>/songs`. |
| `.github/workflows/ci.yml`      | Pushes to `main` and PRs: format, lint, typecheck, tests, then test packages as workflow artifacts.                                                                                                                                                                         |
| `.github/workflows/release.yml` | `v*` tags: `scripts/check-release-tag.mts`, lint, tests, packages on Ubuntu and Windows, then a GitHub Release with the packages and `SHA256SUMS.txt`.                                                                                                                      |
| `scripts/check-release-tag.mts` | `node scripts/check-release-tag.mts <tag>` fails unless the tag is `v` + the `package.json` version.                                                                                                                                                                        |
| `scripts/release.mts`           | `pnpm release [patch\|minor\|major\|current\|x.y.z] [--skip-checks]`. Requires a clean `main` in sync with `origin`. Runs checks, bumps `package.json`, commits `Release vX.Y.Z`, creates an annotated tag, and pushes `main` and the tag atomically after confirmation.    |
| `scripts/version.mts`           | `parseVersion`, `bumpVersion(version, bump)`, `compareVersions(a, b)` for `x.y.z` versions.                                                                                                                                                                                 |

Only `@tonejs/midi` is a runtime `dependency` (the main process requires it). Everything the renderer uses is bundled by Vite and listed under `devDependencies`, so it isn't shipped twice.
